# Scaffold Skill (React + TypeScript + Vite)

You bootstrap new React applications. Tooling and versions follow the **reference React template** (files documented in `references/template-files.md`); folder layout follows **`react-architecture`** (`app/`, `features/`, `shared/`, `config/`, root `tests/`).

**PREREQUISITES:** Load before scaffolding:
- `react-architecture` — folder structure and dependency rules
- `react-code-style` — naming and import conventions
- `react-configuration` — `appConfig` and env validation
- `react-api-client` — axios clients and interceptors (when auth/API setup needed)
- `react-unit-testing` — Vitest setup and `tests/` layout

**RELATED SKILLS:**
- `react-feature` — add features after scaffold
- `react-typescript` — strict typing defaults

**Reference template:** your organization's React template, if it has one — canonical versions for ESLint, Husky, Vitest, TanStack, Tailwind 4.

---

## Pre-Scaffold Questions (MANDATORY)

**Ask these questions and wait for answers before generating files:**

1. **Project name** — kebab-case folder name (e.g., `order-portal`, `inventory-ui`)
2. **App title** — browser tab title (e.g., `Order Portal`)
3. **Package manager** — `pnpm` (default) / `npm` / `yarn`
4. **Include i18n?** — `react-i18next` setup like the template (yes/no; default **no** for minimal scaffold)
5. **Include MSW?** — local API mocking in dev (yes/no; default **no**)
6. **Initialize shadcn/ui?** — run `shadcn init` after scaffold (yes/no; default **yes**)
7. **Sample feature** — include a minimal `home` feature with one page (yes/no; default **yes**)

**Template → architecture mapping** (when migrating from the full reference template):

| Template path | Scaffold path |
|---------------|---------------|
| `src/routes/` | `src/app/routes/` |
| `src/data/api/clients/` | `src/shared/api/httpClient.ts` |
| `src/utils/env.ts` | `src/config/` (`react-configuration`) |
| `src/components/ui/` | `src/shared/components/ui/` |
| `src/lib/utils.ts` | `src/shared/lib/utils.ts` |
| `src/hooks/` (generic) | `src/shared/hooks/` |
| `src/views/` | `src/features/*/pages/` |

## Package Manager and Node

- **Node:** `>=25` (`.nvmrc` → `25`)
- **Package manager:** `pnpm@11.5.1` (template default)

After generating `package.json`, run:

```bash
pnpm install
pnpm exec husky init
```

## ESLint and Prettier

Copy **`eslint.config.js`** and **`.prettierrc`** from the reference template verbatim, with these adjustments:

- `rootDir: 'src'` and `@` prefix in `no-relative-import-paths` (already in template)
- `unicorn/filename-case`: kebab-case exception for `src/shared/components/ui/*.tsx`
- Test override: disable `react/jsx-no-literals` in `**/*.test.{ts,tsx}` and `tests/**`

Copy **`knip.config.ts`** from template; add `src/app/routes` generated files to ignore if needed.

## Post-Scaffold Steps

Run in order:

```bash
pnpm install
pnpm exec husky init
cp .env.example .env.local
pnpm local          # verify dev server
pnpm test           # verify Vitest
pnpm run check      # verify TypeScript
pnpm run lint       # verify ESLint
```

If **shadcn=yes**:

```bash
pnpm dlx shadcn@latest init
pnpm dlx shadcn@latest add button
```

If **MSW=yes**, add `src/shared/api/msw/` handlers and optional dev bootstrap in `main.tsx` (see template `src/data/api/msw/`).

If **i18n=yes**, add `src/shared/i18n/` and wire `I18nextProvider` in `__root.tsx` (see template `src/translations/`).

## Gotchas

- **Do not** copy demo modules from the full template (planner, file-uploader, etc.) into a greenfield scaffold — start minimal.
- **`index.html`** script src must match entry (`/src/main.tsx`; template still references `main.jsx` — fix to `.tsx`).
- **Router generated file** — commit `routeTree.gen.ts` or document CI generation; template commits it.
- **Auth** — scaffold leaves auth unwired; add per backend in a `features/auth` feature later.
- **Prefer fork** — if your organization maintains a reference React template, forking it then restructuring to `features/shared` may be faster than greenfield; apply the mapping table above.

For full ESLint rules and CSS theme tokens, read `references/template-files.md` in this skill folder.
